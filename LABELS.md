# Repository Labels

This repository uses the following labels to help categorize and triage issues and pull requests. Understanding these labels will help you navigate the project and identify areas where you can contribute effectively.

## Standard Issue Labels

* **`bug`**: Something isn't working as expected. Use this for runtime errors, UI glitches, or incorrect API responses.
* **`enhancement`**: A new feature or an improvement to existing functionality. Use this when requesting a better user experience or a new endpoint.
* **`documentation`**: Improvements, fixes, or additions to documentation (README, CONTRIBUTING, inline docs).
* **`good first issue`**: Great for newcomers! An issue that is relatively simple, well-defined, and a good introduction to the project architecture.
* **`help wanted`**: Extra attention is needed. Maintainers are asking the community for help with this issue because it requires specific expertise or extra bandwidth.
* **`security`**: Pertains to a security vulnerability, dependency audit flag, or security-related improvement (e.g., adding rate limiting).
* **`duplicate`**: This issue or pull request already exists.

## Challenge-Specific Labels (Optional)

If you are participating in the GDG 48-Hour Challenge, maintainers may use these labels to categorize your Pull Requests during evaluation:

* **`challenge-ui`**: Relates to UI/UX improvements (Task 2).
* **`challenge-backend`**: Relates to Backend/API improvements (Task 3).
* **`challenge-docker`**: Relates to containerization and Docker workflows (Task 4).
* **`challenge-ci-cd`**: Relates to GitHub Actions, continuous integration, and deployment pipelines (Tasks 5 & 6).

*Note: Contributors generally do not need to apply these labels themselves; repository maintainers will assign them as needed.*
